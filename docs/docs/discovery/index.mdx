# Skills Discovery

Agent Skills provides **three** ways to load skills into a toolset, plus a
search API for runtime discovery.  The three mechanisms can be combined freely.

## Loading Skills into a Toolset

### 1. Path-based loading

Point `AgentSkillsToolset` at one or more local directories.  Every
sub-directory containing a `SKILL.md` file is discovered automatically when
the toolset is first used.

**When to use:** skills checked into the same repository, or mounted at a
well-known path at runtime (e.g. a Kubernetes shared volume).

```python
from agent_skills import AgentSkillsToolset, SandboxExecutor
from code_sandboxes import CodeSandboxClient

toolset = AgentSkillsToolset(
    directories=["./skills"],           # scanned recursively for SKILL.md
    executor=SandboxExecutor(CodeSandboxClient.create(variant="eval")),
)
```

Expected directory layout:

```
skills/
├── pdf-extractor/
│   ├── SKILL.md
│   └── scripts/
│       └── extract.py
└── data-analyzer/
    ├── SKILL.md
    └── scripts/
        └── analyze.py
```

### 2. Module-based loading

Use `AgentSkill.from_module()` to load skills that are packaged inside an
installed Python library.  Works for both regular packages (with
`__init__.py`) and **namespace packages** (directories without
`__init__.py`, where `__file__` is `None`).

**When to use:** skills distributed as part of a pip-installable package,
such as [`datalayer-skills`](https://github.com/datalayer/skills) (`crawl`, `github`, `pdf`, `image`, `video`…), or the `jokes` example in `agent-skills` itself.

```python
from agent_skills import AgentSkill, AgentSkillsToolset, SandboxExecutor
from code_sandboxes import CodeSandboxClient

toolset = AgentSkillsToolset(
    skills=[
        AgentSkill.from_module("agent_skills.skills.jokes"),
        # pip install "datalayer-skills[skills]"
        AgentSkill.from_module("datalayer_skills.skills.crawl"),
        AgentSkill.from_module("datalayer_skills.skills.pdf"),
    ],
    executor=SandboxExecutor(CodeSandboxClient.create(variant="eval")),
)
```

`from_module()` imports the module, resolves its directory, and delegates
to `AgentSkill.from_skill_md()` — no extra configuration needed.

### 3. Entrypoint-based loading (automatic)

Installed Python packages that declare entrypoints in the
**`agent_skills.skills`** group are discovered **automatically** when the
toolset initialises.  No explicit configuration is required — just install
the package and the skills appear.

**When to use:** distributing skills as standalone pip-installable packages
that consumers can install independently.  This is the recommended approach
for sharing skills across teams or publishing them on PyPI.

```python
from agent_skills import AgentSkillsToolset, SandboxExecutor
from code_sandboxes import CodeSandboxClient

# Entrypoint skills are found automatically — no skills= or directories= needed
toolset = AgentSkillsToolset(
    executor=SandboxExecutor(CodeSandboxClient.create(variant="eval")),
)
```

The package registers its skills in `pyproject.toml`:

```toml
[project.entry-points."agent_skills.skills"]
whoami = "datalayer_skills.skills.whoami"
```

Each key is a skill name and each value is a dotted Python module path
that contains a `SKILL.md` file (the same layout used by
`AgentSkill.from_module()`).

To disable entrypoint scanning (e.g. for testing), set
`discover_entrypoints=False`:

```python
toolset = AgentSkillsToolset(
    discover_entrypoints=False,
    executor=SandboxExecutor(CodeSandboxClient.create(variant="eval")),
)
```

You can also call the discovery function directly:

```python
from agent_skills import discover_entrypoint_skills

for skill in discover_entrypoint_skills():
    print(f"{skill.name}: {skill.description}")
```

### Combining all three

The three approaches stack freely.  Skills loaded via `skills=` are merged
with any skills discovered from `directories=` and from entrypoints:

```python
toolset = AgentSkillsToolset(
    directories=["./skills"],           # local / custom skills
    skills=[
        AgentSkill.from_module("agent_skills.skills.jokes"),
    ],
    # discover_entrypoints=True (default) — finds installed packages too
    executor=SandboxExecutor(CodeSandboxClient.create(variant="eval")),
)
```

### In a Kubernetes / SaaS pod

In the Datalayer SaaS deployment the agent-runtimes container runs alongside
a Jupyter container in the same pod.  The two loading patterns map to the
two-container architecture as follows:

```
┌─────────────────────────────── Pod ────────────────────────────────────┐
│                                                                         │
│  agent-runtimes :8765                   jupyter :2300                   │
│  ┌──────────────────────────┐           ┌────────────────────────────┐  │
│  │  AgentSkillsToolset      │           │  Jupyter Kernel            │  │
│  │                          │           │  ┌──────────────────────┐  │  │
│  │  Module-based ──────────►│──reads────►  │ skill script code    │  │  │
│  │  (agent_skills pip pkg)  │  script   │  │ (sent as string via  │  │  │
│  │                          │  content  │  │  SandboxExecutor)    │  │  │
│  │  Path-based ────────────►│──reads────►  └──────────────────────┘  │  │
│  │  (/mnt/shared-agent/     │  SKILL.md │                            │  │
│  │   skills/)               │           │  Shared Volume:            │  │
│  └──────────────────────────┘           │  /mnt/shared-agent/        │  │
│                                         │  └── skills/  ◄── also     │  │
│                                         │      accessible here        │  │
│                                         └────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────┘
```

- **Module-based** — `agent-skills` is pip-installed in the image → the
  agent uses `AgentSkill.from_module()` to get skill metadata.  Script
  code is read from the installed package and sent as a string to the
  Jupyter kernel via `SandboxExecutor`.

- **Path-based** — the container entrypoint copies
  `/opt/datalayer/skills/` → `/mnt/shared-agent/skills/` (a Kubernetes
  `emptyDir` shared by both containers).  Set
  `AGENT_RUNTIMES_SKILLS_FOLDER=/mnt/shared-agent/skills` so agent-runtimes
  scans the shared volume for any additional or custom skills.

Regardless of how a skill is *loaded*, **script execution always happens
inside the Jupyter kernel** — the `SandboxExecutor` reads the script file
content from the agent-runtimes side and sends it as Python source code to
the kernel over the Jupyter HTTP API.

## The environment a skill needs, and when it is activated

A skill says in its `SKILL.md` frontmatter which environment variables it
reads, under `env`:

```yaml
---
name: photos
description: Finds photos on the photo services the person has a key for.
env:
  required:            # every one must be set
    - PHOTOS_REGION
  optional:            # read when set, never needed
    - PHOTOS_TIMEOUT_SECONDS
  any_of:              # one at least must be set
    - FIRST_SERVICE_API_KEY
    - SECOND_SERVICE_API_KEY
---
```

- `required` (also written `all_of`): the skill cannot work without each of them.
- `optional`: the skill reads them when they are set and works without them.
- `any_of`: one of them is enough. Each is optional by itself, so it need not
  be repeated under `optional`.

A skill is **activated** when every `required` variable is set and, when it
names some, one at least of `any_of`. A variable set to an empty or blank
value is not set. A skill that declares nothing is always activated.

A skill with no `env` block is read as before: its required variables are the
ones its `## Required Environment Variables` section names in backticks, and
its optional ones those of `## Optional Environment Variables`. Without a
required section, the variables its scripts' docstrings name are required,
except those the optional section names. An `env` block, even an empty one
(`env: {}`), is the whole declaration: the sections are then not read, so an
empty block says the skill needs nothing.

`AgentSkillsToolset` keeps a skill that is not activated out: it is not in
`list_skills` nor in the instructions, and `load_skill`, `read_skill_resource`
and `run_skill_script` answer that it is not found, as for a skill that does
not exist. When skills were given and none is activated, the toolset offers no
tool at all. The environment is read at each call, so a variable set later
activates its skill without building the toolset again.

For an activated skill with optional variables, the listing and `load_skill`
say which are set now (`optional_env_set=…`, **Environment set now**), by
name and never by value, so the agent knows what the skill can do in this run.

```python
skill = AgentSkill.from_module("my_package.skills.photos")
skill.get_required_env_vars()   # ["PHOTOS_REGION"]
skill.get_optional_env_vars()   # ["FIRST_SERVICE_API_KEY", "PHOTOS_TIMEOUT_SECONDS", ...]
skill.get_any_of_env_vars()     # ["FIRST_SERVICE_API_KEY", "SECOND_SERVICE_API_KEY"]
skill.is_activated()            # on os.environ; or is_activated({"PHOTOS_REGION": "eu", ...})
skill.get_inactive_reason()     # "none of FIRST_SERVICE_API_KEY, SECOND_SERVICE_API_KEY set"

toolset = AgentSkillsToolset(skills=[skill])
toolset.get_inactive_skills()   # {"photos": "PHOTOS_REGION not set; none of ... set"}
toolset.get_active_skills()     # {} until its environment is there
```

The toolset decides on the process's environment, with the variables the
current request's identities stand for when a host provides some. Pass
`env={...}` to decide on another mapping, or `enforce_activation=False` to
offer every skill whatever is set. `get_active_skills()` and
`get_inactive_skills()` discover the toolset's directories and entry points
themselves: they answer from the moment the toolset is built.

## Runtime Discovery via the Agent

When `AgentSkillsToolset` is attached to an agent, the agent can discover
skills dynamically through two built-in tools.

### list_skills

Lists all available skills with summaries:

```python
# Agent calls: list_skills()
# Returns:
[
    {
        "name": "data-analyzer",
        "description": "Analyzes datasets and provides insights",
        "tags": ["data", "analysis"],
        "scripts": ["analyze", "summarize"],
        "resources": ["reference"]
    },
    {
        "name": "file-processor",
        "description": "Process files in batches",
        "tags": ["files", "batch"],
        "scripts": ["process", "validate"],
        "resources": []
    }
]
```

### load_skill

Get full details for a specific skill:

```python
# Agent calls: load_skill(skill_name="data-analyzer")
# Returns:
{
    "name": "data-analyzer",
    "description": "Analyzes datasets and provides insights",
    "content": "# Data Analyzer\n\nUse this skill to analyze...",
    "scripts": [
        {"name": "analyze", "description": "Analyze a data file"},
        {"name": "summarize", "description": "Summarize analysis results"}
    ],
    "resources": [
        {"name": "reference", "description": "Reference documentation"}
    ],
    "tags": ["data", "analysis"],
    "allowed_tools": ["filesystem__read_file"],
    "version": "1.0.0"
}
```

The agent calls `list_skills` to browse what is available, then
`load_skill` to get the full instructions before executing a skill script.
